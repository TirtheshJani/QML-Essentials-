# Week 19 — SVM on the quantum kernel; head-to-head vs RBF

**Tier 2 / 2D.2.** Companion to `week19_kernel_svm_train.py`.

## 1. The kernel-SVM pipeline

A precomputed-kernel SVM in scikit-learn is one line:

```python
clf = SVC(kernel="precomputed", C=...).fit(K_train_train, y_train)
clf.score(K_test_train, y_test)
```

`K_test_train` is the asymmetric block $K_{ij} = k(x_i^{\text{test}}, x_j^{\text{train}})$ — the quantum side has to evaluate it explicitly because the kernel is not a closed-form classical function.

## 2. Each kernel gets its proper preprocessing

A common but unfair design is to feed both kernels the same standardised features. Standardised features (mean 0, std 1) are what RBF wants — the bandwidth $\gamma = 1/d$ is calibrated to that scale. The ZZ feature map needs a different scaling: its $(\pi - x_i)(\pi - x_j)$ factor blows up for large $|x|$, and the kernel value oscillates wildly past $2\pi$. The Havlíček paper recommends min-max scaling to $[0, \pi]$, which keeps every encoded angle in one period.

In this script:

- **Quantum kernel** sees `MinMaxScaler(feature_range=(0, π))`-scaled features.
- **RBF kernel** sees `StandardScaler()`-scaled features.

Same data, same labels, same splits. Only the preprocessing — chosen for each kernel's requirements — differs. This is what an honest practitioner would do.

## 3. Cross-validation grid

5-fold stratified CV over $C \in \{0.1, 1.0, 10.0, 100.0\}$, picking the best $C$ per kernel by CV mean. Held-out accuracy reported on the same fixed test set for both. No grid search over kernel hyperparameters: $\gamma$ for RBF is left at the sklearn default ($1/d = 0.25$); reps for the quantum kernel is fixed at 2 (week 20 sweeps it).

## 4. Results (reps = 2, Iris-0-vs-1)

| kernel | best $C$ | CV mean ± std | held-out test |
|-------|--------:|---------------:|--------------:|
| quantum (ZZ feature map, reps=2) | 0.1 | 0.700 ± 0.128 | 0.700 |
| RBF | 0.1 | **1.000 ± 0.000** | **1.000** |

The RBF kernel solves Iris-0-vs-1 perfectly at every $C$ — the data is linearly separable in 4-D and any positive-bandwidth kernel handles it trivially. The quantum kernel reaches **70 %** CV accuracy and the same 70 % on held-out. The kernel is real and PSD (week 18), but *as a similarity measure it is much worse than a Gaussian RBF for this task*.

## 5. Why the quantum kernel underperforms here

Two compounding effects:

- **Kernel concentration.** ZZ feature maps at moderate depth cluster their fidelities around a small constant for almost all input pairs — Thanasilp et al. 2024 show this is generic for sufficiently expressive embeddings. Week 18 reported a mean within-class − between-class gap of just 1.9 pp.
- **No structural fit.** The quantum kernel has no parameters and no inductive bias beyond the encoding's symmetries. Iris features are standardised real numbers with no quantum structure to exploit; the encoding throws away the very linearity that makes the problem easy.

The literature consensus (Schuld 2021 *PRL*, Huang et al. 2021 *Nat. Commun.*) is that quantum kernels can win only when the dataset has structure that maps cleanly onto the encoding — typically datasets *generated by* a quantum process. Iris does not.

## 6. The honest accounting

- RBF: $\mathcal O(n d)$ flops to compute one Gram entry; effectively free on 40 points.
- Quantum: ~2,400 circuit evaluations across `K_train_train` (40 × 40) + `K_test_train` (20 × 40), ~10 s of wall-clock simulation. On real hardware: shot noise on every fidelity, $\mathcal O(10^4)$ shots per pair to hit precision $10^{-2}$, total ~$10^7$ shots — minutes per Gram matrix at best.

There is no runtime regime in which the quantum side wins on Iris. That is the result. It does not rule out quantum kernels in general, only on this dataset with this feature map — exactly the careful claim Schuld and Petruccione argue for.

## 7. What the script verifies

- Both kernels train end-to-end on the same splits with their own preprocessing.
- Both numbers are reported transparently (CV ± std and held-out), no cherry-picking.
- RBF reaches > 0.85 CV (it hits 1.0).
- Quantum kernel reaches > 0.65 CV (it hits 0.70) — the "did not catastrophically fail" sanity bar.
- Test/CV gaps stay below 0.25 — nothing wildly overfit.
